# SmsPigeon 短信鸽

基于 [Air780EHV](https://docs.openluat.com/air780ehv/product/) + [LuatOS](https://docs.openluat.com/osapi/) 的短信转发固件：把收到的短信转发到你的手机、钉钉、飞书、Server酱或企业微信。

**全本地运行**是本项目的核心特性：配置、鉴权、控制全部通过短信完成，固件自身不连接任何远程管理 API——短信内容不经过第三方管理服务，配置只存在模块本地，最大程度保证隐私与安全。

## 功能特性

- **中文句子命令**：`信鸽，状态` 式自然命令（规避运营商对机器特征短信的过滤），全部配置通过短信完成，无需连接电脑
- **多种转发通道**：短信 / 钉钉 / 飞书 / Server酱 / 企业微信，可同时启用
- **白名单鉴权**：默认仅白名单号码可下发命令（初始化时自动登记第一个号码）
- **密码模式**：可选将 `信鸽` 前缀替换为自定义密码（支持中文），与白名单相互独立、可叠加。
  密码猜测的成本模型：默认白名单开启（AND 语义，不在名单者构不成猜测通道）、
  猜错的"密码前缀"短信不是命令、会作为普通短信**转发给机主**（每次尝试即告警）、
  攻击者按条付费且 4–16 字符空间穷举不经济——因此不设失败锁定
  （可被任意号码远程触发的锁定反而构成对机主的拒绝服务）。
- **IMEI 初始化**：首次使用必须 `信鸽，初始化，<IMEI>`，防误配防冒配；已初始化不可重复初始化
- **防捡漏自毁**：检测到换卡、或连续第 3 次无卡开机，自动恢复出厂
- **离线优先**：短信通道不依赖蜂窝数据网络，无流量也可转发
- **来电提醒**：收到来电时向全部已启用的转发目标推送提醒（含来电号码，
  固件不接听不挂断）；`信鸽，关闭来电提醒` 可关。配合手机侧呼叫转移
  可避免漏接电话（见 FAQ「能否用命令设置呼叫转移」）
- **心跳报平安**：`信鸽，设置心跳，<小时>` 定时向转发目标推送在线摘要
  （信号+转发统计），默认关；无人值守部署的"静默死亡"早发现。
  纯网络通道免费，短信通道启用时按间隔计话费
- **转发过滤**：`信鸽，拉黑，<号码>` 黑名单 + `信鸽，添加过滤词，<词>`
  关键词（可批量），命中静默丢弃并计数（`信鸽，统计` 可查），运营商
  营销短信不再白白烧转发话费；只滤转发、不碰命令鉴权
- **验证码提取**：验证码类短信转发时首行附 `[验证码:xxxx]`，通知栏
  预览直接看到验证码，免点开全文；`信鸽，关闭验证码` 可关（默认开）
- **运行统计**：`信鸽，统计` 查看累计转发/失败/丢弃/过滤/待发，
  `信鸽，清零统计` 归零——排障"到底转没转"一目了然
- **失败暂存重发**：全部通道失败的转发暂存（≤5 条，护闪存寿命），
  网络恢复自动重发或 `信鸽，重发` 手动排空；重试一次仍失败则丢弃
  （不打环）
- **断网自愈**：连续 30 分钟无网络注册（4G 假死）自动重启，无人值守
  场景免人工断电
- **远程发短信**：`信鸽，发送短信，<号码>，<内容>` 控制本机 SIM 卡向外发短信
- **配置导出/导入**：`信鸽，导出配置` 把全部配置导出成一条可原样转发
  的短信，新设备 `初始化` 后转发回去即完成迁移（合并语义、重复导入
  幂等）；密码不随导出；疑似导出内容绝不进转发通道（token 防泄漏闸）
- **可扩展**：转发通道为插件式注册表，新通道=一个文件+一行注册
- **状态灯**（整机开发板 NET 灯）：快闪=无网络、慢心跳=待初始化、常亮=正常、三连闪=收到短信

## 硬件与烧录

- 合宙 Air780EHV 核心板（或自绘电路的 Air780EHV 模组）+ 能收发短信的 SIM 卡
- 内核固件：Air780EHV LuatOS 固件 **V2018 或更高**
  （[固件版本说明](https://docs.openluat.com/air780ehv/luatos/firmware/version/)）；
  固件种类（编号）选择见下方「LuatOS 固件选择」

烧录步骤（Luatools）：

1. 打开 Luatools，进入「项目管理测试」，新建项目；
2. 选择本仓库根目录作为脚本目录，入口脚本 `main.lua`，
   脚本目录内全部 `.lua` 文件勾选下载；
3. 选择 Air780EHV 对应的 LuatOS 固件（.soc）；
4. 核心板插 USB、插 SIM 卡，按 Luatools 提示下载（开机+下载模式）；
5. 下载完成自动重启运行。

> `test/` 目录是单元测试，烧录时无需勾选。

## 硬件兼容性

固件的可移植性边界是 `sp_platform.lua`（硬件差异 API 唯一出口），其余
全部依赖 LuatOS 标准库（sms/fskv/http/crypto/mobile/rtos）。在合宙
Air780E 家族内，功能差异取决于**芯片平台**与**有无内置音频**：

| 型号 | 平台 | 验证状态 | 短信转发 | 来电提醒 | 说明 |
|---|---|---|---|---|---|
| Air780EHV | EC718 | **已验证** | 全网通 | ✅ | 本固件的开发与测试基准 |
| Air780EHM / Air780EGH | EC718 | 理论支持 | 全网通 | ✅ | 与 EHV 同平台，官方 demo 同项目分发；EGH 额外带 GNSS |
| Air780EPV 系列（EPV/EPVH/EPVZ 等） | EC718P-V | 理论支持 | 全网通 | ✅ | 带 Audio Codec 的 EP 变体（VoLTE） |
| Air780EP / EPG / EPZ | EC718P | 理论支持 | 移动/联通 | ❌ | 无音频：电信卡短信与来电提醒均不可用，其余功能不受影响 |
| Air780EPM / Air780EPS | EC718 | 理论支持 | 移动/联通 | ❌ | 低功耗版（EPM 仅支持 LuatOS 开发）；无内置音频，来电提醒预期不可用 |
| Air780E / Air780EG | EC618 | 理论支持 | 移动/联通 | ❌ | [官方 wiki 明确](https://wiki.luatos.org/chips/air780e/mcu.html)：不支持电信网络短信、不支持 VoLTE |

- **来电提醒的降级行为**：无音频平台收不到 CC_IND 来电事件，
  `sp_call` 静默不触发，固件其余功能（短信转发/命令/心跳/统计）
  完全正常；
- **电信卡注意**：电信网络的 SMS 依赖 VoLTE/IMS 能力，仅 EC718 平台
  全网通（已验证型号 EHV 官方固件含 TTS+VOLTE）；EC618 平台
  （Air780E/EG）官方明确不支持；
- **不适用**：Air700E/Air600E（TDD-only，仅移动）；Air724UG 等
  旧平台未测试、不承诺；
- 「理论支持」均为**未在真机验证**的推断（依据官方芯片平台资料与
  LuatOS 库支持矩阵），实测通过/失败都欢迎提 issue 补充本表；

## LuatOS 固件选择

Air780E 家族 Flash 有限装不下全部核心库，官方按核心库组合拆分出
多种固件（EHV/EHM/EGH/EGG/EHU/EHN 家族 32+16 种），
[官方固件版本页](https://docs.openluat.com/air780ehv/luatos/firmware/version/)
有完整矩阵。本固件的依赖：`sms`/`fskv`/`http`/`crypto`/`mobile`/
`rtos`（所有固件标配）+ `cc`（来电提醒）+ 电信短信（可选，取决于 SIM）。

**固件编号规则：1-99 号是 32 位固件，101-199 号是 64 位固件**，
同号功能一致仅位数不同（差异见
[官方说明](https://docs.openluat.com/common/core_32_64/)）。
同时具备 `cc` 与电信短信的只有 1/2/8/13 四系：

| 固件 | cc 来电提醒 | 电信短信 | TTS | fs 文件系统 | 适用 |
|---|---|---|---|---|---|
| **1 号 / 101 号** | ✅ | ✅ | ✅ | 768KB | **推荐**——全功能档，本项目实测 101 号 |
| 2 号 / 102 号 | ✅ | ✅ | — | 640KB | 精简备选（本项目不依赖 TTS） |
| 8 号 / 108 号 | ✅ | ✅ | — | 1536KB | 需要大文件系统时的备选 |
| 其余各号 | — | — | 部分有 | 各异 | 无 `cc`：来电提醒收不到事件自动失效，短信转发不受影响（移动/联通卡） |

- 脚本所需 API 自 V2018 起可用（见「硬件与烧录」），生产部署建议直接
  用最新版（V2050，2026-08-21 发布）；官方"历史版本"页的旧包仅限
  对比测试，不建议生产使用；
- EHM/EGH/EGG/EHU/EHN 与 EHV 共用同一固件矩阵与下载渠道，同号
  选择规则直接套用；EPM/700ECP（8 种）与 EGP（3 种）变体较少，
  在各自资料中心固件页按"`cc` 是否在列 + 是否需要电信短信"同法挑选；
- Air780EPV 可刷 Air780EP 固件正常运行（但无 VoLTE，官方 wiki）；
  反向不可——EP 硬件刷 EPV 固件不能正常工作。

## 快速上手

假设模块 IMEI 为 `861234567890123`，你的手机号为 `13800138000`：

```
[手机] 发送短信:  信鸽，初始化，861234567890123
[模块] 回复:     OK:SmsPigeon 已初始化
                 13800138000 已加入白名单
                 发送 信鸽，状态 查看状态

[手机] 信鸽，增加转发号码，13800138000   ← 短信转发到自己手机
[模块] OK:13800138000 已加入短信转发列表

[手机] 信鸽，开启短信转发
[模块] OK:短信转发已开启

[手机] 信鸽，帮助                         ← 查看全部命令
```

此后任何号码发给模块的短信都会转发到你的手机，默认不带任何标识前缀；
可用 `信鸽，设置前缀，<文本>` 自定义（如 `【短信鸽】`）。
多设备转发到同一群时可用 `信鸽，设置标识，<文本>` 区分来源
（默认自动取 SIM 本机号码尾 4 位，物联网卡未写号码则不携带）。

钉钉/飞书/Server酱/企业微信通道的配置示例、命令细节与鉴权规则见
**[docs/commands.md](docs/commands.md)**。

## 工作原理

```
                    ┌────────────────────────────────────┐
   任意发件人 ──SMS──▶│ sp_forward 收到短信                 │
                    └──────┬─────────────────────────────┘
                           │
              是命令(信鸽/密码前缀)？──否──▶ 过滤：黑名单/过滤词
                           │                    │ 命中即静默丢弃(计数)
                           ▼                    ▼ 未命中
                  sp_commands 命令处理        转发分发 sp_channels
                  （鉴权→执行→短信应答）          ├─▶ 短信通道（离线）
                                                ├─▶ 钉钉 Webhook
                                                ├─▶ 飞书 Webhook
                                                ├─▶ Server酱
                                                └─▶ 企业微信（消息推送）
```

- 未初始化：不转发任何短信，只接受 `信鸽，初始化`，其余静默丢弃；
- 命令与转发互斥：一条短信要么是命令，要么被转发；
- 换卡 / 连续 3 次无卡开机 → 恢复出厂，回到未初始化状态。
- 来电提醒（`sp_call`）与心跳（`sp_heartbeat`）汇入同一转发队列，与短信
  共用通道与限速；
- 全部通道失败的转发暂存，网络恢复自动重发；连续 30 分钟无网络注册
  自动重启自愈。

## 状态灯指示（整机开发板）

Air780Exx 整机开发板左上角的 NET 灯由模组 GPIO27 控制（官方开发板手册
明确其工作逻辑由用户自定义），固件定义如下语义：

| 灯效 | 含义 |
|---|---|
| 快闪（约 2Hz） | 网络未注册/无 SIM——异常，需要关注 |
| 慢心跳（2 秒周期短亮） | 已注册但固件未初始化——等待 `信鸽，初始化` |
| 常亮 | 已初始化且网络已注册——正常工作中 |
| 三连闪 | 收到一条短信（活动指示） |

核心板没有此灯：`sp_platform.lua` 中 `LED_GPIO` 置 nil 即停用该功能；
其它板型若灯的亮灭逻辑相反，改 `LED_ACTIVE_HIGH = false`。

### 本地跑单元测试

```bash
# Windows（经 pip install lupa 的内嵌 Lua 运行时）
python test/run_with_lupa.py

# Linux / CI（原生 Lua 5.3）
lua5.3 test/run_tests.lua
```

测试覆盖命令解析、鉴权门禁组合、配置持久化/恢复出厂、换卡与无卡复位、
转发统计/过滤/暂存重发、心跳布防、断网自愈、main.lua 全链路装配冒烟
（10 个测试文件 450 项断言）。HTTP 通道的真实推送与硬件行为（短信收发、
SIM 事件时序、CC_IND 来电事件）无法在纯 Lua 环境模拟，以下硬件验收
清单为准。

### 硬件验收清单

烧录后逐项实测：

1. 未初始化时：发普通短信和 `信鸽` 均无应答、无转发；
2. `信鸽，初始化，<IMEI>` 收到 OK，错误 IMEI 收到 `ERROR`；
3. 重复 INIT 收到 `ERROR`；
4. 非白名单号码发命令无应答；
5. 配置短信转发后，其他号码发短信能收到转发文本；
6. 配置钉钉（建议加签）后能收到群消息（需 NTP 成功，观察日志
   `NTP 对时成功`）；
7. 来电提醒：另一台手机拨打模块号码，转发目标收到含来电号码的提醒
   （物联网卡未开通语音时无来电，本项跳过）；
8. 验证码提取：触发一条平台验证码短信，转发文本首行带 `[验证码:xxxx]`；
9. 心跳：`信鸽，设置心跳，1` 后约 1 小时收到在线报平安
   （不想等可跳过，逻辑已被单测覆盖）；
10. `信鸽，恢复出厂` 后回到未初始化；换卡后同样自动复位；
11. 拔卡连续 3 次开机后复位（日志 `连续第 3 次无卡开机`）；
12. 状态灯：未初始化慢心跳、初始化后常亮、收到短信三连闪、拔卡后快闪。
13. 配置迁移：`信鸽，导出配置` → `恢复出厂`+`初始化` → 原样转发导出
    短信，收到 `OK:导入完成` 且配置完整（顺带验证长短信双向链路）。

### 添加新转发通道

1. 新建 `sp_chan_xxx.lua`，实现并注册通道接口：

   ```lua
   local sp_channels = require "sp_channels"
   sp_channels.register {
       key = "xxx",          -- 与 sp_config.defaults().fwd 中的键一致
       name = "某平台",
       needs_net = true,     -- HTTP 类通道为 true
       is_configured = function(chcfg) ... end,   -- 配置是否完整
      send = function(msg, chcfg) ... end,        -- 返回 true 才算成功；false/nil 均为失败(可带原因)
   }
   ```

2. 在 `sp_config.defaults().fwd` 增加 `xxx` 默认配置结构；
3. 在 `sp_commands.lua` 的 `CH_ALIAS` 增加命令别名（如 `XX`）；
4. `main.lua` 增加 `require "sp_chan_xxx"`。

### 移植到其它 LuatOS 模组

业务模块只通过 `sp_platform.lua` 访问硬件差异 API（IMEI/ICCID/信号/重启），
其余 LuatOS API（sms/fskv/http/crypto）在 Air780E 系列上通用。
移植 Air780EPM/EHM/EGH 等型号通常只需确认 fskv 分区可用、
`rtos.bsp()` 返回值，必要时在 `sp_platform.lua` 内做适配。

## 常见问题

### 发命令没反应 / 收不到转发

1. **先看日志有没有"收到短信"**：固件对每条到达的短信（无论是否命令）
   都会先打印 `I/user.sp_forward 收到短信 <号码> 长度 <字节数>`（出于
   安全不打印正文——命令短信含密码/token，第三方短信内容同样不应落
   日志），随后打印 `短信中心时间戳`（SCTS，运营商下发时刻——与你
   发送时刻相差大即说明运营商延迟投递）。需要看 PDU/正文排障时，发
   `信鸽，调试，开` 临时开启内核短信调试日志（`sms.debug`，默认关闭，
   重启自动复位），开启后内核会打印 `CMI_SMS_NEW_MSG_IND` / `D/sms` 行。
   - 有"收到短信"但命令无应答 → 命令格式问题：半角符号、IMEI 是否与
     日志 `self_info` 行一致（见 docs/commands.md）；
   - 内核行都没有 → 短信根本没到模组，继续往下。
2. **物联网卡限制（最常见）**：物联网卡（如 ICCID `8986112…` 号段）
   常未开通点对点短信接收，部分专用号段普通手机号根本无法发送；
   已知案例中短信在运营商侧滞留 6 分钟以上才投递（对时间戳即可确认）。
   请联系运营商开通"点对点短信"，或先换普通消费级 SIM 卡验证。
   也可能是**内容特征过滤**（如命令含连续 11 位手机号被当垃圾短信拦截）：
   命令采用中文句子本身就是规避手段（实测全中文命令可达）；放慢发送节奏、
   启用密码模式也有帮助。
3. **验证短信链路**：在 `main.lua` 的 `sys.run()` 前临时加入自检任务，
   确认模块能发出短信并获知号码（验证后删除）：

   ```lua
   sys.taskInit(function()
       sys.waitUntil("CC_IND", 30000)
       log.info("自检", "本机号码", mobile.number(0) or "卡商未写入")
       sms.send("138xxxxxxxx", "SmsPigeon 自检短信")  -- 改成你的手机号
   end)
   ```

   手机收到后直接回复该短信发 INIT 命令，回信地址即模块号码；
   出栈正常而入栈收不到 → 坐实卡的接收限制。
4. **发送侧**：以普通文本短信发送（勿用 iMessage/5G 消息/彩信），
   使用 11 位裸号码，换一部手机交叉验证。
5. 若内核有 `CMI_SMS_NEW_MSG_IND` 行但没有 `收到短信` 行，属于固件
   问题，请附带该段日志提 issue。**贴日志前先脱敏**：涂抹手机号、
   IMEI/ICCID；若开过 `信鸽，调试，开`，PDU 行与正文可能含密码、
   webhook token 或他人短信内容，务必一并清除。

### 能否用命令设置呼叫转移？

不能。呼叫转移需向网络发送补充业务指令（USSD 码 `**21*号码#` 或
AT+CCFC），而 Air780EHV 的 LuatOS 固件不暴露 USSD/CCFC 接口
（官方 mobile 库仅 38 个函数：imei/iccid/number/状态/APN 等，
无补充业务类；cc 通话库也只有拨号/挂断/接听/录音）。因此固件层
无法设置或查询呼叫转移。

**可行替代**：呼叫转移（含无条件转移）注册在运营商网络侧，随 SIM 卡
生效，与终端无关——把 SIM 卡装进手机拨 `**21*目标号码#` 设置一次，
装回模块即长期生效；`##002#` 取消全部转移。注意多数物联网卡未开通
语音，来电本身不存在，转移亦无从谈起。

**避免漏接的建议**（结合固件的来电提醒）：固件只提醒、不接听。若想
真正接到来电，用手机为这张卡设置呼叫转移，两种打法：

- **未接通转移（推荐）**：手机上拨 `**61*<你的手机号>#`——来电先在
  模块侧响铃（固件照常发出来电提醒），无人接听时网络自动转接到你
  的手机，提醒与接听两全；
- **无条件转移** `**21*<你的手机号>#`：来电直接转走，模块侧收不到
  来电事件，**来电提醒不会触发**（短信转发不受影响）。
